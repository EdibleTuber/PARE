# `pare-tui` Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A Textual terminal UI that replaces `pare-cli` as the operator surface and renders live device output beside the conversation, starting with an interactive UART console pane.

**Architecture:** A Textual `App` in `pare/tui/`. Three independent task families that must never block one another: one long-lived task owning `DaemonConnection.receive()`, one owner task per pane holding its own `MCPClient`, and the Textual event loop. Panes read their source directly rather than through the daemon's tool pool; pane activity is logged back through the daemon as a PARE-local registered protocol message.

**Tech Stack:** Python 3.12+, Textual (8.2.x), `agent_core` (`DaemonConnection`, `MCPClient`, protocol registry), `mcp`, pytest + pytest-asyncio (`asyncio_mode = "auto"`).

**Spec:** `docs/superpowers/specs/2026-09-18-pare-tui-design.md` — read it alongside this plan. Task rationale lives there; this plan does not restate it.

## Global Constraints

- `requires-python = ">=3.12"` (matches PARE's `pyproject.toml`). The dev venv is 3.12.3.
- **Never use `DaemonConnection.chat()`, `.command()` or `.command_stream()`.** `agent_core/client.py:57-63`: `receive()` "Does NOT hold `_read_lock`. Do not interleave with `chat()`/`command()`/`command_stream()` on the same connection; `readline()` races on the shared `StreamReader` and produces interleaved or out-of-order results." The TUI uses only `connect()`, `send()`, `receive()`, `close()`.
- **`MCPClient.connect()` and `close()` must run in the same task.** `agent_core/workers/client_pool.py:2-24` — anyio binds a cancel scope to the entering task; closing elsewhere raises `RuntimeError: Attempted to exit cancel scope in a different task than it was entered in` and leaks the connection. Calling `call_tool` from a foreign task is safe; only teardown carries the affinity requirement.
- **Target bytes are untrusted.** UART output is arbitrary bytes from an untrusted board — which is why the worker returns base64 (`pare-hardware-mcp/src/pare_hardware_mcp/contract.py:79-80`). Never render raw; see Task 12.
- **No changes to `agent_core`.** Every extension point used here already exists: `register_message` (`agent_core/protocol/__init__.py:17`), `Agent.handle_other` (`agent_core/agent.py:147`).
- **Assert relationships, not literals.** No magic counts, no exact-pane-text snapshots — both rot on the next legitimate change.
- Tests live flat in `tests/` as `test_tui_*.py`, matching the existing layout. `asyncio_mode = "auto"` means async tests need no decorator.
- Run the suite with `./.venv/bin/pytest`.

```python
"""The PARE TUI application: chat beside live device panes.

Replaces pare-cli as the operator surface. See
docs/superpowers/specs/2026-09-18-pare-tui-design.md.

from __future__ import annotations

import os
from datetime import datetime

from textual.app import App, ComposeResult
from textual.widgets import Footer, Header

from pare.config import load_config


def _new_channel_id() -> str:
    """A fresh channel per launch, so a session starts clean instead of
    replaying cli-default. Mirrors pare/cli.py:_new_channel_id."""
    return datetime.now().strftime("tui-%Y%m%d-%H%M%S")

    """The application shell. Layout and wiring arrive in later tasks."""

        super().__init__()
        self.socket_path = socket_path
        self.channel_id = channel_id
        self.cwd = cwd

    def compose(self) -> ComposeResult:
        yield Header()
        yield Footer()


def main() -> None:
    config = load_config()
    app = PareTUI(config.socket_path, _new_channel_id(), os.getcwd())
    app.run()
```

```python
# pare/protocol.py
"""PARE-local protocol messages, registered with agent_core's registry.

Generic primitives (Chat, Command, StreamChunk, Response, Error, ToolProgress,
approval messages) live in agent_core.protocol. Registering here means
encode_message/decode_message round-trip these types too — PAL does the same
in pal/protocol.py.
"""
from dataclasses import dataclass

from agent_core.protocol import register_message


@register_message
@dataclass
class PaneActivityMessage:
    """One slice of operator-visible device activity, logged through the
    daemon because the TUI cannot open the capture store itself — the daemon
    holds an exclusive flock on it (pare/capture_store.py:59-69).

    kind: "sent" (the operator wrote these bytes) or "observed" (they came
    back from the device). cursor_start/cursor_end locate the slice in the
    worker's cursor space; for "sent" they are equal, since a write occupies
    no range in the read cursor.
    """
    source: str
    session: str
    kind: str
    data_b64: str
    cursor_start: int
    cursor_end: int
    channel_id: str | None = None
    cwd: str | None = None
    type: str = "pane_activity"
```

### Task 3: `handle_other` — log without blocking the read loop

**Files:**
- Modify: `pare/agent.py` (add `handle_other`; `PareAgent` has none today)
- Test: `tests/test_tui_handle_other.py`

**Interfaces:**
- Consumes: `pare.protocol.PaneActivityMessage` (Task 2); `PareAgent._bind_store(ctx)`, the existing context manager used by `handle_chat` (`pare/agent.py:346`) and `handle_command` (`:332`).
- Produces: `PareAgent.handle_other(self, msg, ctx: HandlerContext) -> None` — returns immediately, never yields.

**No implementation code, deliberately.** This is a cancellation and ordering
problem; write it against the real `handle_chat`/`handle_command` and the real
daemon loop.

**The invariant (spec R3).** `agent_core/daemon.py:136` awaits `handle_other`
**inline in the connection's read loop** — unlike `ChatMessage` and
`CommandMessage`, which are dispatched with `asyncio.create_task`
(`daemon.py:119-126`). So any time spent inside `handle_other` is time the
connection is not reading. The next message on that socket is not read until it
returns — **including `ToolApprovalResponseMessage`**, whose routing at
`daemon.py:176` is what resolves a pending approval. A synchronous capture-store
write inside `handle_other` therefore lets a slow disk stall an approval the
operator has already answered.

**Requirements:**
1. `handle_other` must return without awaiting the store write. Hand the record to a task or an in-process queue owned by the agent.
2. The hand-off must be bounded. An unbounded queue turns a wedged writer into unbounded memory; a bounded one must drop or block deliberately, and say which in a comment.
3. Messages that are not `PaneActivityMessage` must fall through to the base-class behaviour, not be swallowed. `agent_core/agent.py:147`'s default is a no-op, and other message types reach the same entry point.
4. The store must be resolved through `_bind_store(ctx)` like every other handler, so the per-project store and `cwd` resolution stay identical to the chat path.
5. A write that fails must be surfaced, not swallowed (spec R4) — log it, and make the failure observable to the app.

**What the tests must discriminate:**

- **The blocking test.** Send a `PaneActivityMessage` whose store write is made deliberately slow, then immediately send a `ToolApprovalResponseMessage` on the same connection, and assert the approval is routed without waiting for the write. **This test MUST be verified failing against a naïve synchronous handler before the fix lands** — run it against a version that awaits the write inline and confirm it fails. A version that passes both ways is testing nothing.
- **Fall-through.** An unrelated registered message type reaching `handle_other` must not raise and must not be treated as pane activity.
- **Store binding.** A message carrying a `cwd` must write to the store that `cwd` resolves to, not to the daemon's default.
- **Failure surfacing.** A store write that raises must not be silent.

- [ ] **Step 2:** Run it against the current code (no `handle_other`) and confirm it fails.
- [ ] **Step 3:** Write a deliberately synchronous `handle_other` — await the write inline. Run the test and **confirm it still fails.** This is the step that proves the test discriminates; do not skip it.
- [ ] **Step 4:** Make it non-blocking per requirement 1 and 2. Run the test and confirm it passes.
- [ ] **Step 5:** Write the fall-through, store-binding and failure-surfacing tests. Run them.
- [ ] **Step 6:** Run the full suite: `./.venv/bin/pytest -q`

### Task 4: The daemon session — exactly one reader

**Files:**
- Create: `pare/tui/session.py`
- Test: `tests/test_tui_session.py`

**Interfaces:**
- Consumes: `agent_core.client.DaemonConnection`; `agent_core.protocol` message types.
- Produces:
  - `class DaemonSession` with `async def start(self) -> None`, `async def stop(self) -> None`, `async def send_chat(self, text: str) -> None`, `async def send_command(self, name: str, args: str) -> None`, `async def send(self, msg: object) -> None`, and a subscription hook `def subscribe(self, handler: Callable[[object], None]) -> None` invoked for every decoded message.
  - Constructor: `DaemonSession(socket_path: Path, channel_id: str, cwd: str)`.

**No implementation code, deliberately** — this is the single-owner invariant,
and the failure mode is silent corruption rather than an exception.

**The invariant (spec I1).** Exactly one task consumes
`DaemonConnection.receive()` for the process lifetime. `agent_core/client.py:57-63`
states why: `receive()` does not take `_read_lock`, so a second consumer — or
any use of the `chat()`/`command()`/`command_stream()` helpers, which do — races
on the shared `StreamReader` and yields interleaved or out-of-order messages.
Nothing raises. A turn simply renders wrong, intermittently.

**Requirements:**
1. One reader task, started by `start()`, cancelled and awaited by `stop()`.
2. `send_chat`/`send_command` stamp `channel_id` and `cwd` on every outgoing message, as `pare/cli.py` does today.
3. Subscribers are invoked synchronously from the reader task and must not be able to wedge it — a raising subscriber is logged and the loop continues.
4. Connection loss is an event subscribers can see, not a silent stop.

**What the tests must discriminate:**

- **Single-consumer enforcement.** A test that fails if the module references `\.chat\(`, `\.command\(` or `\.command_stream\(` on a `DaemonConnection`, and fails if a second `receive()` consumer can be started. Interleaved reads corrupt silently, so this cannot be left to an integration test noticing something looked odd.
- **Ordering.** Messages arriving in a known order reach a subscriber in that order.
- **A raising subscriber does not stop the reader.** Assert that a later message still arrives after an earlier subscriber raised.
- **`stop()` is idempotent** and does not raise when called on a session that never started.

**The subtlety being ported.** A `reasoning=off` turn streams
`StreamChunkMessage` tokens *and then* emits a `ResponseMessage` carrying the
same joined text. A `reasoning=on` turn emits only the `ResponseMessage`. The
CLI resolves this in `_TurnPrinter` (`agent_core/adapters/cli.py:118-146`) by
suppressing a `ResponseMessage` that merely repeats what was streamed. A TUI
that skips this renders every non-reasoning answer twice.

```python
A test covering only one shape leaves the other silently broken: reasoning=off

same bug and are tested together deliberately.
```

```python
# pare/tui/widgets/transcript.py
"""Turn accumulation for the chat transcript.

Ported from agent_core/adapters/cli.py:118-146 rather than imported: the CLI's
_TurnPrinter returns (text, end) tuples shaped for print(), and it is private.
The wire behaviour it encodes is what matters here, not its signature.
"""
from __future__ import annotations

from agent_core.protocol import (
    ErrorMessage,
    ResponseMessage,
    StreamChunkMessage,
)


def is_turn_end(msg: object) -> bool:
    """A turn closes on ResponseMessage or ErrorMessage — the same rule the
    REPL's drain loop uses (agent_core/adapters/cli.py:202-203)."""
    return isinstance(msg, (ResponseMessage, ErrorMessage))


class TurnAccumulator:
    """Decides what text each message contributes, so a streamed turn's answer
    is not rendered twice. One instance per session; reset() between turns."""

    def __init__(self) -> None:
        self._streamed: list[str] = []

    def reset(self) -> None:
        self._streamed.clear()

    def feed(self, msg: object) -> str | None:
        if isinstance(msg, StreamChunkMessage):
            self._streamed.append(msg.token)
            return msg.token
        if isinstance(msg, ResponseMessage):
            if self._streamed and msg.text == "".join(self._streamed):
                return None      # duplicate of the stream: already rendered
            return msg.text
        if isinstance(msg, ErrorMessage):
            return f"Error: {msg.error}"
        if isinstance(msg, ToolProgressMessage):
            return f"  [{msg.tool}({clip_args(msg.arguments)})]"
        if isinstance(msg, LearningCandidateProposalMessage):
            return f"\n[Learning candidate: {msg.title}]\n{msg.body}\n"
        # Never drop an unrecognised type: a message we cannot render is still
        # evidence something happened. Mirrors _default_format's fallback
        # (agent_core/adapters/cli.py:115).
        return f"[unrendered {type(msg).__name__}]"
```

```python
# pare/tui/sources/fake_console.py
"""An in-memory ConsoleSource for development and tests.

The UART pane is built against this, not against the Pi: bench integration is
a separate plan, and this double can produce conditions a real board cannot be
made to produce on demand — a ring-buffer eviction, a suspended capture, a
session that dies mid-read.
"""
from __future__ import annotations

from pare.tui.sources.base import ConsoleSlice


class FakeConsoleSource:
    """Scriptable console. feed/drop/gap/die/fail_next set up a condition;
    read() reports it the way console_read would."""

    def __init__(self, session: str | None = "fake-1") -> None:
        self._session = session
        self._buf = bytearray()
        self._dropped = 0
        self._gaps: list[int] = []
        self._alive = True
        self._fail: Exception | None = None
        self.sent: list[bytes] = []

    # --- scripting -----------------------------------------------------
    def feed(self, data: bytes) -> None:
        self._buf.extend(data)

    def drop(self, n: int) -> None:
        self._dropped += n

    def gap(self, at: int) -> None:
        self._gaps.append(at)

    def die(self) -> None:
        self._alive = False

    def fail_next(self, exc: Exception) -> None:
        self._fail = exc

    # --- ConsoleSource -------------------------------------------------
    async def attach(self) -> str | None:
        return self._session

    async def status(self) -> dict:
        return {"session": self._session, "alive": self._alive}

    async def send(self, session: str, data: bytes) -> None:
        if self._fail is not None:
            exc, self._fail = self._fail, None
            raise exc
        self.sent.append(bytes(data))

    async def read(self, cursor: int = 0, limit: int | None = None) -> ConsoleSlice:
        if self._fail is not None:
            exc, self._fail = self._fail, None
            raise exc
        available = bytes(self._buf[cursor:])
        applied = len(available) if limit is None else min(limit, len(available))
        data = available[:applied]
        next_cursor = cursor + len(data)
        gaps = [g for g in self._gaps if cursor <= g <= next_cursor]
        dropped, self._dropped = self._dropped, 0
        return ConsoleSlice(
            data=data,
            next_cursor=next_cursor,
            dropped=dropped,
            remaining=len(self._buf) - next_cursor,
            capture_gaps=gaps,
            alive=self._alive,
            limit_applied=applied,
        )
```

### Task 10: The real source — an owner task per pane

**Files:**
- Create: `pare/tui/sources/mcp_console.py`
- Test: `tests/test_tui_mcp_console.py`

**Interfaces:**
- Consumes: `agent_core.workers.client.MCPClient`; `ConsoleSource`, `ConsoleSlice` (Task 7).
- Produces: `class McpConsoleSource(ConsoleSource)` constructed as `McpConsoleSource(endpoint: str, worker_prefix: str = "")`, with `async def start(self) -> None` and `async def stop(self) -> None` around the `ConsoleSource` methods.

**No implementation code, deliberately.** This is the cancel-scope task
affinity, and it is the single most likely place in this plan for a silently
wrong implementation.

**The invariant.** `agent_core/workers/client_pool.py:2-24`:
`MCPClient.connect()` enters two nested anyio cancel scopes, and anyio binds a
scope to the task that entered it. **`close()` must therefore run in the same
task that ran `connect()`.** Closing from another task raises
`RuntimeError: Attempted to exit cancel scope in a different task than it was
entered in` and leaves the connection alive. "Dispatch is unaffected: calling a
client from a foreign task is safe, and only teardown carries the affinity
requirement."

**The trap this task exists to avoid:** the natural Textual shape is to
`connect()` in `on_mount` and `close()` in `on_unmount`. Those are different
tasks. Copy `client_pool.py`'s owner-task pattern instead — one task connects,
parks on a stop event, and closes in its own `finally`, the same task
throughout.

**Requirements:**
1. One owner task per source. `connect()` and `close()` both run inside it.
2. `stop()` signals the owner and waits with a **bound**. An owner that will not stop must not hang the app's shutdown.
3. Tool names carry the worker prefix the daemon would apply — `agent_core`'s `tool_factory` builds `f"{worker.name}_{tool_name}"`, so the bare contract name `console_read` dispatches as `hardware_console_read` through PARE. Connecting **directly** to the worker means the bare name is correct. Get this right by reading the worker's `contract.py`, and make the prefix explicit in the constructor rather than implicit.
4. Replies are JSON strings — the worker's `_ok` is `json.dumps(fields)` (`pare-hardware-mcp/src/pare_hardware_mcp/tools.py:105-106`) and errors are `{"error": ...}` from `_err` (`:109-110`). `data_b64` must be base64-decoded into `ConsoleSlice.data`. An `{"error": ...}` reply is a failed read, not an empty one.
5. The read limit passed must respect the worker's clamp; `limit_applied` in the reply is the authority on what was actually read, not the value requested.

**What the tests must discriminate:**

- **Same-task teardown.** Start the source, then `stop()` it, and assert no `RuntimeError` about cancel scopes and that the client actually closed. Verify this test **fails** against a deliberately wrong version that closes from the caller's task — otherwise it is not testing the affinity at all.
- **Bounded stop.** An owner that ignores the stop signal must not block `stop()` indefinitely.
- **Error replies are failures.** An `{"error": "no such session"}` reply must raise or surface as an error, never render as an empty read — an empty read means "nothing new", which is a different and reassuring thing.
- **Base64 decoding.** A reply whose `data_b64` decodes to non-UTF-8 bytes must reach `ConsoleSlice.data` as bytes, undamaged.

```python
# pare/tui/sanitize.py
"""Untrusted bytes → text safe to put on screen.

Target output is arbitrary bytes from a board under test
(pare-hardware-mcp contract.py:79-80), and tool arguments reaching the approval
modal are equally untrusted. Neither may carry terminal escapes into the
renderer.
"""
from __future__ import annotations

import re

# Everything in C0 except \n and \t, plus DEL and the C1 range. \r is included
# deliberately: a carriage-return run overwrites a line in place, which is a
# display-integrity problem even though \r is not an escape introducer.
_UNSAFE = re.compile(r"[\x00-\x08\x0b-\x1f\x7f-\x9f]")

_MAX_ARG = 200
_MAX_TOTAL = 1000


def for_display(data: bytes) -> str:
    """Decode with replacement (a board emits arbitrary bytes, not valid
    UTF-8) and strip anything that could move the cursor or repaint."""
    text = data.decode("utf-8", errors="replace")
    return _UNSAFE.sub("�", text)


def clip_args(arguments: dict) -> str:
    """Render tool arguments for the approval modal: sanitised, per-argument
    clipped, then total-clipped. Mirrors the CLI's _sanitize_args
    (agent_core/adapters/cli.py:31-46)."""
    rendered = []
    for key, value in (arguments or {}).items():
        s = _UNSAFE.sub(" ", str(value))
        if len(s) > _MAX_ARG:
            s = s[:_MAX_ARG] + f"...(+{len(s) - _MAX_ARG} chars)"
        rendered.append(f"{key}={s}")
    out = ", ".join(rendered)
    if len(out) > _MAX_TOTAL:
        out = out[:_MAX_TOTAL] + "...(truncated)"
    return out
```

Note: `for_display` strips `\r`, which means a device using bare `\r` for
progress lines renders as replacement characters rather than overwriting.
That is the intended trade — display integrity over fidelity. If it proves
wrong against a real board, change it with a test that says why.
