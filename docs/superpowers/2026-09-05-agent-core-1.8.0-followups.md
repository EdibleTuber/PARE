# agent_core v1.8.0 — carried follow-ups

Deliberately deferred during the dynamic-worker-lifecycle build (plan:
`plans/2026-09-05-dynamic-workers-agent-core.md`). Each was triaged by the final
whole-branch review and judged safe to carry. None blocks the release; all are
cheap, and several interact.

## Security-adjacent (fix together — they share one root)

- **`external_mcp` kind flip discards the wire-derived per-tool ratchet.** The
  floor ratchet added in the final pass applies to every kind and survives a flip,
  but the per-tool wire high-water does not, because `_resolve_declared` returns
  early for `external_mcp`. Only reachable if a worker's `kind` changes across a
  reload, which requires a mutable catalog — not possible today, since the catalog
  is fixed at boot.
- **`invalid_advertised` remains partly lossy.** A high-water escalation over a
  malformed advertised tier still overwrites `tier_source` to `"wire"`, so the
  tampering signal is lost in the case it exists for. Escalation stays correct;
  only forensics degrade.
- **A truthy non-dict `meta` that is itself a valid tier string** (e.g.
  `meta = "critical"`) is now treated as an advertised wire tier and feeds the
  high-water mark. Escalate-only, so fail-safe, but it is an escalation sourced
  from malformed data.

## Robustness

- **`_fail` ordering:** it calls `executor.remove_worker` before `remove_spec`; if
  the former ever raised, `_load_locked`'s `suppress(Exception)` would swallow it
  and leave the spec registered.
- **Double `_fail` on a second cancellation** overwrites `_errors[name]` with
  `"CancelledError: "`, losing the original `connect_timeout` / `list_tools_failed`
  message.
- **`MCPClientPool.close_all` is sequential** with a 5s bound per worker, so
  shutdown is O(N x 5s) for a wedged fleet.
- **A caller cancelled during `connect()`'s error-path `_reap`** propagates out of
  `_load_locked` without running `_fail`, so `add_spec` residue survives until the
  next `load()` (`add_spec` is idempotent).

## Test coverage

- `load_autoload` recording `last_error` has no regression test.
- No test interleaves a parked approval future with a concurrent
  `load`/`unload`/`reload` beyond the two added in the final pass.
